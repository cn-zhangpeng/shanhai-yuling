## 二、可行性结论（分"我能做"与"我不能做"）

### 2.1 我能全包的（代码工程 100%）

| 模块 | 说明 |
|---|---|
| Rust 后端 | 窗口（透明/无边框/置顶/跳任务栏/不抢焦点）、分区鼠标穿透、托盘菜单、开机自启、单实例锁、配置读写与原子持久化、多屏与 DPI 坐标换算、全屏应用检测 |
| TS 前端 | 渲染器抽象层、状态机、动作调度、交互事件、台词库管理、计时器、设置面板 |
| 渲染接入 | Live2D Cubism Web SDK 5 接入（`model3.json` 加载、参数/表情驱动）；二期 VRM（three.js + @three-vrm）路由 |
| 打包发布 | `tauri build` 便携包 + WebView2 缺失引导页 + 首次运行资源释放 |
| 文档 | 本需求文档、状态机伪代码、穿透伪代码、构建说明、验收清单 |

**环境实测（本机）**：Node `v22.23.2`、npm `10.9.8`、Python `3.13.18`、WebView2 运行时 `157.0.4341.46`（已装，满足要求）。
**缺失且必须先补**：Rust 工具链（`rustc`/`cargo`/`rustup` 均无）、MSVC C++ Build Tools（Tauri Windows 编译必需）、`git`（仓库初始化与依赖拉取）。合计下载约 4–6 GB，一次性安装 30–60 分钟。**这一步我可以直接代做**，也是 M0 里程碑。

### 2.2 我不能代做的（硬边界，必须承认）

| 事项 | 为什么做不了 | 替代方案 |
|---|---|---|
| **Live2D 成品模型**（`.moc3` + `model3.json` + 贴图集） | 需要①分层 PSD 手绘（头部/眼睛/嘴/头发/手臂/书本/铅笔独立层）②在 Cubism Editor 里人工建网格、绑参数、调物理与动作。绑定是纯手工活，我无法操作编辑器完成，也无法产出可用于绑定的高质量分层 PSD | 见 §3 决策 D4：**一期先用"分层 PNG 伪 Live2D"跑通整条链路**，真模型到位后只替换渲染器实现，不动其余代码 |
| 冉冉本人的形象还原 | 需真实照片参考 + 手绘转 Q 版，且"保留脸型/五官/发型辨识度"是人工审美判断 | 你提供正脸+侧脸照片 2–3 张，我出草图方向；最终立绘建议外包或你自己画 |

> 一句话：**程序我做得到、做得完；模型资产我做不到。** 所以方案必须让"没有模型也能跑"，否则整个项目会卡在美术上。

### 2.3 Live2D 授权与编辑器限制（v1.0 未评估，会直接影响成本）

- **SDK 授权**：Cubism SDK / Cubism Core 遵循 Live2D Proprietary Software License。**一般用户与小规模企业（年营收 < 1000 万日元）免签出版许可、免费**；本机自用属此范围。Core 二进制允许随应用一起分发。
- **Cubism Editor 免费版硬限制**：贴图**仅 1 张、上限 2048 px**，且 ArtMesh / 参数 / 变形器 / 部件数量有上限，**超限直接无法保存**。一个含书本、铅笔、多手势的坐姿 Q 版角色，大概率会顶到上限。
- **结论**：一期若走真 Live2D，需预留 **Cubism PRO 订阅**（个人版约 $13/月）或主动压缩图层数。这条必须写进预算，否则做到一半会卡在"存不了盘"。

## 三、技术方案修订（8 个决策项）

### D1 窗口与鼠标穿透（最高优先级难点，v1.0 只有目标没有方案）

**定稿：窗口贴精灵包围盒（不是全屏），穿透由 Rust 侧"轮询 + alpha 掩码"判定。**

方案对比：

| 方案 | 做法 | 结论 |
|---|---|---|
| A 轮询+掩码 | Rust 30 Hz `GetCursorPos` → 命中窗口 rect → 查前端上传的 32×32 alpha 掩码 → 仅在结果变化时调 `set_ignore_cursor_events` | ✅ **采用**。无权限要求、无杀软风险、精度够、可防抖 |
| B layered 逐像素 alpha | `WS_EX_LAYERED` 让 alpha=0 区域天然穿透 | ⚠️ 备选。WebView2 走 DirectComposition，透明度与命中测试是否联动需实机验证，不作为主路径 |
| C 全局低级鼠标钩子 `WH_MOUSE_LL` | 全局捕获鼠标 | ❌ **禁止**。被杀软误报、需高权限、与游戏反作弊冲突 |

实现要点（缺一条就会体验崩坏）：
1. 前端把模型渲染到离屏 canvas，**100 ms 节流**取 alpha>0.15 的掩码（32×32 或 64×64），只在变化超阈值时 IPC 推给 Rust，**不要每帧推**。
2. Rust 只在**状态翻转**时调用系统 API（每帧调用会导致光标闪烁、拖拽断裂）。
3. **双阈值 + 120 ms 最小切换间隔**防抖；鼠标在边缘抖动时不得反复翻转。
4. **拖拽/右键菜单期间强制锁 `ignore=false`**；`mouseup` 无法可靠送达时，用 `GetAsyncKeyState(VK_LBUTTON)` 兜底判定拖拽结束。
5. 拖拽用 Tauri `start_dragging()`（系统级拖动，平滑不掉帧），结束后读 `outer_position` 写回配置。
6. 坐标全部用**物理像素**（`GetCursorPos` 是物理像素，`outer_position/outer_size` 也是），前端仅用 `devicePixelRatio` 做显示换算；**负坐标（副屏在主屏左侧）必须处理**。
7. 窗口自身：`decorations:false`、`transparent:true`、`shadow:false`（Win11 下 `true` 会出现 1 px 白边）、`skipTaskbar:true`、`alwaysOnTop:true`、`focused:false`（不抢焦点，避免打字时被夺焦点）、`noRedirectionBitmap:true`（消除创建时白闪）。

→ 伪代码见 **附录 B.2**。

### D2 渲染栈：一期**去掉 PixiJS**

- v1.0 写"渲染引擎 PixiJS + Live2D Web SDK"，但一期明确"不做粒子、不做复杂光影"，Pixi 属于纯冗余（+400 KB 包体 + 一层适配风险）。
- 定稿：一期直接使用官方 **Cubism SDK for Web** 自带 WebGL 渲染器，自建 `Renderer` 接口；二期若真要做背景道具/特效，再引 Pixi 并置于**独立 canvas 图层**，绝不与 Live2D 混用同一渲染上下文。
- 同时规避第三方 `pixi-live2d-display` 的版本矩阵坑（Pixi 6 / 7 / Cubism 5 兼容长期不稳定，维护弱）。

### D3 资源与打包：外置优先、内置兜底

```
ShanhaiYuling/                     ← 整个目录可拷走 = "绿色便携"
├── ShanhaiYuling.exe              ← 单文件程序本体
├── assets/creatures/              ← 外置资源，直接加文件夹即生效，无需编译
│   └── ranran/
│       ├── creature.json          ← 统一清单（v1.0 缺此文件，"解耦"落不了地）
│       ├── model3.json / textures/ (真 Live2D)
│       └── sprite/ (分层 PNG 过渡方案)
└── config/
    ├── global-config.json
    └── creatures/ranran.config.json
```

- 加载走 Tauri `asset` 协议 + `convertFileSrc`，CSP 放行 `asset:` 与 `http://asset.localhost`。
- **首次运行**：若 `assets/` 不存在，从 exe 内置 resources 释放一份到安装目录 → 用户可自由增删改。
- 资源类型由 `creature.json` 的 `type` 字段路由：`live2d | vrm | sprite`。v1.0 说"程序自动识别 model3.json / vrm"，靠**扫描文件名**识别不可靠，显式声明更稳。

### D4 模型资产策略：一期先跑"分层 PNG 伪 Live2D"

这是本版**最重要的调整**，目的是解开"卡在美术"的死锁：

| 阶段 | 渲染实现 | 能力 | 何时切换 |
|---|---|---|---|
| 一期 MVP | `sprite` 渲染器：分层 PNG（身/头/眼/嘴/手臂/书本）+ 参数化变换（呼吸缩放、眨眼换图、转头位移+倾斜、张嘴换图） | 观感约等于"低配桌面宠物"，够支撑全部交互与状态机 | 立刻可做 |
| 一期终版 | `live2d` 渲染器：真 `model3.json` | 真 Live2D 级表现 | 美术产出 `.moc3` 后，**只换渲染器实现**，状态机/交互/配置全不改 |

两个渲染器共用同一接口：`mount / update(dt) / applyParams / playMotion / getHitMask / destroy`。这样美术晚交付**不会阻塞任何程序工作**。

### D5 配置与持久化

- **位置优先级**：`exe同目录/config/`（可写则用，保证便携）→ 不可写时回落 `%LOCALAPPDATA%\ShanhaiYuling\`（Program Files 场景）。
- **必须带 `schemaVersion`**，启动时校验并迁移；文件损坏则改名 `.bak` 并回默认值。
- **原子写**：写 `.tmp` → `rename`，避免断电/崩溃留半文件；写入前取文件锁，防多进程竞争。
- `global-config.json` 字段：`schemaVersion / window{x,y,w,h,scale,monitorId} / currentCreature / features{greeting,audio,topmost,autostart,clickThrough} / mode(quiet|lively) / doNotDisturb{enabled,start,end} / render{fpsCap}`。
- 每个生灵独立 `ranran.config.json`：`lines / motions / weights / greetingProbability / 称呼(relation)`。
- **`relation` 字段**：v1.0 台词硬编码"爸爸"，改为配置项（`爸爸 / 妈妈 / 我的名字`），否则换个家庭就不能用。

### D6 单实例与多生灵

- `tauri-plugin-single-instance`：第二次启动只唤起已有实例设置面板，不新开窗口。
- 多生灵 = 同一窗口内多个 `Renderer` 实例（各自独立包围盒与掩码，穿透判定取"任一命中"），**不做多进程**。

### D7 状态机：把"不打断"改造成**参数叠加层**，而不是状态抢占

v1.0 写"主动问候不会打断正在进行的动作，动作播放完成后触发"——纯排队会让问候延迟到 3 分钟后，体验很差。

定稿：**主干动作单通道串行（不可抢占）+ 头/眼/表情做 additive 参数层（可随时叠加）**。

- 主干状态：`REST`（托腮发呆/呼吸/打哈欠）、`STUDY`（伏案书写/翻本子）、`PLAY`（把玩文具/晃脚/张望）。
- 叠加层：`LOOK_AT_CURSOR`、`BLINK`、`GREET_WAVE`（挥手）、`REACT_CLICK`。
- 交互优先级：`DRAG > CLICK > HOVER > GREET > 主干动作`。
- 问候触发：主干动作继续，叠加"转头看向鼠标 + 挥手 + 台词"；若正处于"伏案书写"的笔尖落纸段，则等该**微动作段**结束（不是整段动作结束）。
- 随机切换：权重表 + 冷却（同状态 2 分钟内不回切）+ 过渡插值（300–600 ms ease），**禁止硬切**。

→ 伪代码见 **附录 B.1**。

### D8 静默与自保（v1.0 完全缺失）

| 场景 | v1.0 行为 | v1.1 要求 |
|---|---|---|
| 用户在全屏游戏/演示/视频会议 | 依然置顶 + 依然问候 → 严重干扰 | 检测前台全屏窗口 → **自动隐藏 / 屏蔽问候与音效**，退出全屏后恢复 |
| 免打扰时段（如 22:30–07:00） | 无 | 设置面板可配时段，期间不问候、降低动作频率 |
| 窗口被完全遮挡 | 仍 60 fps 渲染，白烧 GPU | 检测遮挡 → 降到 5 fps 或暂停 rAF；隐藏时停渲染 + 停轮询 |
| 休眠唤醒 / 分辨率变化 / 拔插显示器 | 无处理 | 唤醒后重算窗口 rect、掩码、DPI；位置越界则拉回主屏 |
| WebGL 不可用（远程桌面、虚拟机、老显卡） | 无处理 | 降级为静态 sprite + 提示"渲染降级"，保证不崩 |
| 任务栏/多虚拟桌面 | 无 | 跟随当前虚拟桌面；不进入 Alt+Tab 列表 |
| 截屏/录屏 | 透明窗口可能被截成黑块 | 列入二期"录屏自动隐藏"，一期在文档标注已知问题 |

## 四、美术与资产交付修订

### 4.1 动作清单：一期从 11 项砍到 6 项（MVP）

| 保留（一期） | 理由 |
|---|---|
| Idle：呼吸起伏 + 眨眼 + 轻微转头 | 底座，必须有 |
| 伏案书写（循环含落笔/抬眼） | 核心场景，冉冉人设锚点 |
| 托腮发呆 | 休憩态，弱打扰 |
| 挥手打招呼 | 主动问候必备 |
| 点击反应（比耶 / 挥手） | 被动交互必备 |
| 注视鼠标（头/眼跟随） | 悬浮反馈，体验关键 |

| 推迟（二期） | 理由 |
|---|---|
| 打哈欠、揉眼睛、翻本子、挠头、晃小脚、小幅蹦跳、把玩文具、张嘴 | 每项都要新增参数与动作曲线，绑定工时陡增；一期不做也不影响"活起来"的观感 |

### 4.2 交付物清单（供美术/外包对齐）

1. 坐姿主稿立绘（正面 + 微侧，透明底 PNG，3000 px 级）
2. 分层 PSD（头/眼/嘴/发/手臂/书本/铅笔，图层命名规范附后）
3. 表情 & 动作参考表（对应 §4.1 六项）
4. `model3.json` + 贴图集（**单张 ≤ 2048 px**，否则需 PRO）
5. 分层 PNG 过渡包（若走 D4 一期：身/头/眼（睁闭）/嘴（闭/张）/手臂 6 层即可）

### 4.3 台词库修订

- JSON 结构：`{ "category": "greeting|click|idle", "text": "...", "weight": 1, "cooldownSec": 300, "modeTags": ["quiet","lively"] }`
- 追加规则：同类台词 5 分钟内不重复；连续两轮不得同句；免打扰时段整类跳过。
- 孩童口吻保留，但**去掉"我乖乖写作业啦"这类可能引发家长焦虑的暗示句**（可选替换为"我在画画呀"）。此为建议，不强制。

### 4.4 儿童肖像约束（v1.0 未提，必须写）

- 原始照片、分层母版与任何可还原真实长相的素材**不进公开仓库**：`.gitignore` 排除 `art/`、`*.psd`、`*.cmo3`、`*.moc3`、`references/`。
- 仓库里只保留重绘后的 Q 版成品帧（作者为监护人，已确认可公开）。
- 若日后分发程序本体，可继续携带该角色；如需中性版本，另做一套示例生灵即可。

## 五、性能与验收指标（v1.0 写"低占用"但无数字，无法验收）

| 指标 | 目标 | 测量口径 |
|---|---|---|
| 空闲 CPU | ≤ 2% 单核（≈ 系统总占用 ≤ 0.5%，8 核机） | 无交互静置 60 s，任务管理器/`typeperf` 采 8 s 均值 |

| 安装包体积 | 便携目录 ≤ 40 MB（不含模型资源） | 构建产物统计 |

| 里程碑 | 内容 | 依赖 | 估算 |

## 附录 B：两份关键伪代码（v1.0 承诺的配套内容，此处直接给骨架）

### B.1 状态机（主干串行 + 叠加层）

```ts
type MainState = 'REST' | 'STUDY' | 'PLAY';
type LayerId = 'look' | 'blink' | 'wave' | 'clickReact';

// 主干：单通道，不可抢占
class ActionQueue {
  private current: Motion | null = null;
  private queue: Motion[] = [];
  play(m: Motion, urgent = false) {
    if (urgent) { this.current?.cancel(); this.current = m; m.start(); return; }
    this.current ? this.queue.push(m) : this.startNext();
  }
  update(dt: number) {
    this.current?.update(dt);
    if (this.current?.finished) this.startNext();
  }
}

// 叠加层：与主干并行，权重按优先级合成，不打断主干
class ParamMixer {
  base: Params;                       // 主干输出
  layers: Map<LayerId, { p: Params; w: number; prio: number }> = new Map();
  apply(l: LayerId, p: Params, w = 1, prio = 0) { this.layers.set(l, { p, w, prio }); }
  resolve(): Params {
    let out = { ...this.base };
    for (const [, { p, w, prio } ] of [...this.layers].sort((a, b) => a[1].prio - b[1].prio))
      for (const k in p) out[k] = mix(out[k] ?? 0, p[k], w);   // 线性插值，禁硬切
    return out;
  }
}

// 问候：不等整段动作结束，只等"微动作段"安全点
function tryGreet() {
  if (!cfg.features.greeting) return;
  if (inDoNotDisturb() || isFullscreenAppActive()) return;
  if (!queue.atSafePoint()) { queue.onceSafePoint(tryGreet); return; }  // 微动作段结束再触发
  mixer.apply('look', lookAtCursor(600), 1, 10);
  mixer.apply('wave', waveParams(), 1, 20);
  say(pickLine('greeting'));
}
```

### B.2 穿透判定（Rust 侧）

```rust
// 前端 ~100ms 节流上传 32x32 掩码；此处只做坐标换算 + 翻转判定
async fn hit_test_loop(win: WebviewWindow, state: Arc<Mutex<MaskState>>) {
    let mut last_hit = false;
    loop {
        let mut st = state.lock().unwrap();
        if st.suspended { drop(st); sleep(100).await; continue; }   // 隐藏/拖拽/菜单中不判
        let (cx, cy) = get_cursor_pos_physical();
        let rect = (win.outer_position().unwrap(), win.outer_size().unwrap());
        let inside = cx >= rect.0.x as i32 && cy >= rect.0.y as i32
                  && cx <  (rect.0.x as i32 + rect.1.width as i32)
                  && cy <  (rect.0.y as i32 + rect.1.height as i32);
        let hit = inside && st.mask.sample(
            (cx - rect.0.x as i32) as f32 / rect.1.width as f32,
            (cy - rect.0.y as i32) as f32 / rect.1.height as f32, 0.15,
        );
        drop(st);
        if hit != last_hit {                                        // 只在翻转时动系统 API
            win.set_ignore_cursor_events(!hit).ok();
            last_hit = hit;
        }
        sleep(Duration::from_millis(33)).await;                     // 30Hz
    }
}
```
