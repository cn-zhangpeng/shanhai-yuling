## 二、可行性结论

### 2.1 我能全包的

| 模块 | 说明 |
|---|---|
| Rust 后端 | 窗口（透明/无边框/置顶/跳任务栏/不抢焦点）、分区穿透、托盘、开机自启、单实例锁、配置原子持久化、多屏与 DPI 换算、全屏应用检测 |
| TS 前端 | 渲染器抽象、状态机、动作调度、交互事件、台词库、计时器、设置面板 |
| 渲染接入 | Live2D Cubism Web SDK 加载 `model3.json`；`.moc3` 模型族；二期 VRM 路由 |
| **资产生产线** | **AI 出图 → 分层素材包 → PSD2Live 自动绑定 → `model3.json` + `.moc3`，全流程可由我驱动（见 §2.4）** |
| 打包发布 | `tauri build` 便携包 + WebView2 缺失引导页 + 首启资源释放 |
| 文档 | 本需求文档、状态机与穿透伪代码、分层命名规范、构建与验收说明 |

### 2.2 边界：什么我做得到、什么只能"接近"

| 事项 | 结论 | 说明 |
|---|---|---|
| **`.moc3` / `model3.json` 模型文件** | ✅ **能自动生成，不需要人工绑定** | 用开源项目 **PSD2Live**（GPL-3.0，v3.8.0，2026-11-14 发布）：输入分层 PSD → 自动识别图层语义、自适应三角网格、头身变形器链、五官参数、待机/眨眼/点头动作、头发物理 → 一键导出 `.cmo3` 与 `.model3.json` + `.moc3` 文件族。实测有 Windows x64 便携包（147 MB，自带 Java 运行时，免装 JDK） |
| **分层素材（PSD）** | ✅ 走 AI 生成 + 自动分层 + 命名规范 | 见 §2.4 的 L1/L2 两步。也可外包给美术，两条路并行不冲突 |
| **冉冉本人辨识度（脸型/五官/发型）** | ⚠️ 只能"接近"，不保证 likeness | 需你提供 2–3 张正脸/微侧照片作为图像参考；AI 出图能锁定发型与脸型轮廓，但"像不像自家孩子"是审美判断，需要你来回挑 2–3 轮 |
| **绑定质量对标商业绑定师** | ⚠️ 达不到 | 自动绑定质量取决于分层质量，官方自己也记录了失败样本。目标是"桌宠场景够用、动作不撕裂"，不是 VTuber 直播级 |
| **给我一张照片就全自动出成品模型** | ❌ 做不到 | 中间必须有"挑图 + 分层校对"两道人工判断，我会把这两道压缩到"你只做选择，不做操作" |

### 2.3 授权与成本（v1.1 判断有误，此处更正）

| 事项 | 更正后的结论 |
|---|---|
| Cubism Editor | **一期完全不需要**。`moc3` 由 PSD2Live 直接产出，不必再用官方编辑器打开/保存，因此**"FREE 版单贴图 2048 超限无法保存"这条限制不再构成阻塞**，也不必为它订阅 PRO |
| Cubism SDK / Core（运行时） | 仍需 `live2dcubismcore.min.js` 才能在自家程序里渲染 `moc3`。个人自用属"一般用户"，免出版许可；Core 允许随应用分发 |
| PSD2Live 的 GPL-3.0 | **只作为独立工具使用**（输入 PSD、输出模型文件），**不链接、不打包进 Tauri 程序**，因此不传染本项目代码；导出产物是数据资产，README 明确"交付的模型不依赖 PSD2Live" |
| 零授权备选路线 | PSD2Live 另可导出 `.p2lrt`（配套 **MIT** 许可的 Rust 运行时 / WebAssembly 播放器），可完全绕开 Live2D 专有 Core。一期不采用（生态与调试成本高），登记为**授权政策变化时的退路** |

### 2.4 ★ 资产生产流水线（v1.2 新增，本方案的核心解法）

三层，逐层可验收，任何一层失败都不致命：

```
L1  AI 出图            image_gen / image_edit（带参考图锁角色一致性）
      │                 产出：坐姿主立绘 + 6 组表情/口型变体
      ▼
L2  分层与合成         Python（Pillow + opencv + 区域分割/差分）+ 人工点名校对
      │                 产出：names.psd（符合 PSD2Live 命名规范的图层树）
      ▼
L3  自动绑定与导出     PSD2Live（GUI 或 CLI/MCP）
      │                 产出：model3.json + *.moc3 + textures + physics3 + motion3
      ▼
     载入 Tauri 程序     Cubism Web SDK 渲染 → 状态机驱动参数
```

#### L1 AI 出图（替代"手绘立绘"）

- 主图：`image_gen` 一次出 3–4 个候选（Q 版坐姿、柔和平涂/淡水彩国风、正面与微侧各一张），你挑 1 张定稿。
- 变体：以定稿主图为参考图，用 `image_edit` 派生——**闭嘴/张嘴**、**睁眼/闭眼（或上眼睑压下）**、**笑眼**、**手臂抬起（挥手）**、**托腮**。每次只改一个局部，保证其余像素不动。
- 出图约束（写进 prompt）：纯色或透明底、身体基本正立（便于自动绑定的头身轴向判断）、不要叠图层效果/文字、发丝根部清晰。

#### L2 分层与合成（关键，决定绑定质量）

PSD2Live 官方给出的素材要求，直接转成本项目的**分层清单**：

| 层 | 必需 | 说明 |
|---|---|---|
| 后发 | ✅ | 必须与前发分开，遮挡区域留余量 |
| 身体 / 衣服 | ✅ | 含手臂分层的可绑挥手；不分层则无挥手 |
| 手臂（左/右） | 建议 | 画在同一层时可用"按网格拆分图层"补救 |
| 头/脸 | ✅ | 脸型轮廓齐整 |
| 眼白（左右） | ✅ | 瞳孔被眼皮遮住的部分要保留 |
| 瞳孔（左右） | ✅ | 与眼白分层，才能做眨眼与视线 |
| 上睫毛/上眼睑（左右） | ✅ | 眨眼参数靠它压下来 |
| 嘴（闭）+ 嘴（张） | ✅ | 有张嘴素材才能做口型/说话；细分上下牙/舌更佳 |
| 眉毛 | 建议 | 表情差分 |
| 书本 / 铅笔（道具） | 可选 | 独立层可单独摆动；不做也不影响主体 |

自动化手段（我用 Python 实现，逐项可回退到人工点选）：
1. **抠主体**：`rembg`/U²-Net 去掉背景 → 得到身体轮廓层。
2. **五官区域切分**：按主图关键点框选（眼框、嘴框）→ 在框内做颜色聚类 + 连通域，分离眼白/瞳孔/睫毛。
3. **差分取层**：用 L1 的"闭嘴/张嘴""睁眼/闭眼"两张变体做像素差分 → 直接得到可用的差分层，比人工切更准。
4. **命名**：按规范批量重命名图层（中/英/日/韩任一种官方都能识别，本项目统一用英文，例：`hair_front` / `hair_back` / `body` / `face` / `eye_white_L` / `eye_pupil_L` / `eyelid_upper_L` / `mouth_close` / `mouth_open`）。
5. **合成**：`Pillow` 写 PSD（`psd-tools` 或 `psd-tools3`），保留图层顺序与透明通道。

#### L3 自动绑定与导出

- GUI 走法：`文件 → 新建 → 从 PSD 新建工程…`（`Ctrl+Shift+O`）→ 开始页选预设（最小/默认/**完整**）→ 核对"图层"表里的部件类型与侧别（识别错的直接改）→ 预览工作区看动作与物理 → `Ctrl+G` 导出 Cubism 格式（目标版本 3.0–5.3，默认 5.0）。
- CLI 走法（便于我批量重跑）：`PSD2Live --input .\art\ranran.psd --output .\build\ranran`，产物直接落到 `assets/creatures/ranran/live2d/`。
- **MCP 走法**（返工利器）：PSD2Live 启动后监听 `http://127.0.0.1:23871/mcp`，提供 180+ 操作、原子批量与试运行。自动绑定某处不对时，我可以通过 MCP 直接改图层归属/参数/网格，不必你手动点。
- **导出后必做的校验**（缺一不可）：
  1. 用官方 Cubism Web SDK 的示例页加载该 `model3.json`，确认能出图、能驱动参数；
  2. 检查 `moc3` 目标版本与我们所引 SDK 版本是否匹配（PSD2Live 默认 5.0，SDK 需 ≥ 对应版本）；
  3. 统计纹理集尺寸与总体积（单角色目标 ≤ 15 MB）。

#### 失败模式与降级

| 失败 | 现象 | 处理 |
|---|---|---|
| 分层错位 | 眨眼时眼白露边、张嘴穿模 | 回到 L2 重切该层；或 MCP 里改部件归属 |
| 自动绑定不达标 | 转头时五官漂移、头发穿插 | 降级方案一：Cubism Editor 的 AI"自动生成变形器"做人工校对（约 2–4 小时/角色）；降级方案二：本期改用 `sprite` 分层 PNG 渲染（见 §3 D4 兜底） |
| 纹理超限 | 导出体积膨胀 | 逐层降纹理密度 / 关闭 2× 高清化 |
| 模型跑不动 | 桌宠里掉帧 | 降参数更新频率、合并图层、必要时降纹理到 1024 |

## 三、技术方案修订（决策项）

### D1 窗口与鼠标穿透（最高优先级难点，v1.0 只有目标没有方案）

**定稿：窗口贴精灵包围盒（不是全屏），穿透由 Rust 侧"轮询 + alpha 掩码"判定。**

| 方案 | 做法 | 结论 |
|---|---|---|
| A 轮询+掩码 | Rust 30 Hz `GetCursorPos` → 命中窗口 rect → 查前端上传的 32×32 alpha 掩码 → 仅在结果变化时 `set_ignore_cursor_events` | ✅ 采用 |
| B layered 逐像素 alpha | `WS_EX_LAYERED` 让 alpha=0 天然穿透 | ⚠️ 备选，WebView2 走 DirectComposition，需实机验证 |
| C 全局低级鼠标钩子 `WH_MOUSE_LL` | 全局捕获鼠标 | ❌ 禁止：杀软误报、需高权限、与反作弊冲突 |

要点：①掩码 100 ms 节流、只在变化超阈值时 IPC；②只在状态翻转时调系统 API；③双阈值 + 120 ms 最小间隔防抖；④拖拽/菜单期间锁 `ignore=false`，`GetAsyncKeyState(VK_LBUTTON)` 兜底判结束；⑤拖拽用 `start_dragging()`；⑥全用物理像素，处理副屏负坐标；⑦窗口参数 `decorations:false / transparent:true / shadow:false / skipTaskbar:true / alwaysOnTop:true / focused:false / noRedirectionBitmap:true`。伪代码见附录 B.2。

### D2 渲染栈：一期**不用 PixiJS**

一期不做粒子与光影，Pixi 纯冗余（+400 KB 且引入 `pixi-live2d-display` 的版本矩阵坑）。直用官方 **Cubism SDK for Web** 自带 WebGL 渲染器，自建 `Renderer` 接口；二期若真加背景道具/特效，再引 Pixi 放**独立 canvas 图层**。

### D3 资源与打包：外置优先、内置兜底

```
ShanhaiYuling/
├── ShanhaiYuling.exe
├── assets/creatures/ranran/
│   ├── creature.json            ← 统一清单（type/entry/canvas/anchor/motions/relation）
│   ├── live2d/
│   │   ├── ranran.model3.json
│   │   ├── ranran.moc3
│   │   ├── textures/            ← 纹理集
│   │   ├── physics3.json
│   │   └── motion3.json ×N
│   └── sprite/                  ← 降级用分层 PNG（可选）
└── config/{global-config.json, creatures/ranran.config.json}
```

- 走 `asset` 协议 + `convertFileSrc`，CSP 放行 `asset:` 与 `http://asset.localhost`；首启若 `assets/` 缺失则从 exe 内置资源释放一份。
- 类型由 `creature.json` 的 `type`（`live2d | vrm | sprite`）**显式路由**，不靠扫文件名猜。

### D4 模型策略（v1.2 改写）

| 阶段 | 用哪个模型 | 目的 |
|---|---|---|
| 开发期（M1–M2） | **PSD2Live 自带示例工程/示例 PSD 出的模型**（或任一同版本免费示例模型） | 链路、穿透、性能验证与美术无关，绝不等图 |
| 一期交付 | 冉冉真模型（L1→L2→L3 产出） | 正式角色 |
| 受限期兜底 | `sprite` 分层 PNG 渲染器 | WebGL 不可用（远程桌面/虚拟机）时降级，或自动绑定彻底失败时临时顶替 |

`Renderer` 接口统一：`mount / update(dt) / applyParams / playMotion / getHitMask / destroy`，三个实现（live2d / vrm / sprite）可互换。

### D5 配置与持久化

- 位置：`exe同目录/config/`（可写则用）→ 回落 `%LOCALAPPDATA%\ShanhaiYuling\`。
- 必带 `schemaVersion`；损坏改名 `.bak` 回默认；`.tmp` → `rename` 原子写 + 文件锁。
- `global-config.json`：`window{x,y,w,h,scale,monitorId} / currentCreature / features{greeting,audio,topmost,autostart,clickThrough} / mode(quiet|lively) / doNotDisturb{enabled,start,end} / render{fpsCap}`。
- 生灵独立配置：`lines / motions / weights / greetingProbability / relation(称呼)`。

### D6 单实例与多生灵

`tauri-plugin-single-instance`：二次启动只唤起已有实例的设置面板。多生灵 = 同一窗口内多个 `Renderer`，穿透判定取"任一命中"。

### D7 状态机：主干串行 + 参数叠加层

"问候不打断动作"改为**叠加**而非排队：主干 `REST/STUDY/PLAY` 单通道不可抢占；`LOOK_AT_CURSOR / BLINK / GREET_WAVE / REACT_CLICK` 为 additive 参数层，随时并入。优先级 `DRAG > CLICK > HOVER > GREET > 主干`。问候只在"微动作段"安全点让位（不是整段动作播完）。随机切换带权重、冷却（同状态 2 分钟不回切）、300–600 ms 插值，禁硬切。伪代码见附录 B.1。

### D8 静默与自保

| 场景 | 要求 |
|---|---|
| 全屏游戏/演示/视频会议 | 检测前台全屏窗口 → 自动隐藏、屏蔽问候与音效，退出后恢复 |
| 免打扰时段 | 可配（如 22:30–07:00），期间不问候、动作降频 |
| 窗口被遮挡 | 降到 5 fps 或暂停 rAF；隐藏时停渲染 + 停轮询 |
| 休眠唤醒 / 分辨率变化 / 拔插显示器 | 重算窗口 rect、掩码、DPI；位置越界拉回主屏 |
| WebGL 不可用 | 降级 `sprite` 静态渲染 + 提示，不崩 |
| 任务栏 / 虚拟桌面 | 跟随当前虚拟桌面，不进 Alt+Tab |
| 截屏/录屏异常 | 一期记为已知问题，二期处理 |

## 四、美术与资产规范

### 4.1 动作清单：一期 6 项（MVP）

| 保留 | 基于什么样的分层 |
|---|---|
| Idle：呼吸起伏 + 眨眼 + 轻微转头 | 眼白/瞳孔/上眼睑分层 + 头身变形器 |
| 伏案书写（循环含落笔/抬眼） | 手臂层 + 道具层（书本/铅笔） |
| 托腮发呆 | 手臂层（托腮位） |
| 挥手打招呼 | 手臂层（抬起位） |
| 点击反应（比耶/挥手） | 手臂层 + 表情差分 |
| 注视鼠标（头/眼跟随） | 眼白/瞳孔分层 + AngleX/AngleY |

推迟二期：打哈欠、揉眼睛、翻本子、挠头、晃小脚、小幅蹦跳、把玩文具。

### 4.2 资产交付物（改为"AI 素材包 + PSD"）

1. 定稿主立绘（透明底 PNG，≥ 2048 px 短边）
2. 变体图：闭嘴 / 张嘴 / 睁眼 / 闭眼 / 笑眼 / 挥手 / 托腮（各 1 张，透明底）
3. `ranran.psd`：按 §2.4 L2 清单分好层、按命名规范命名
4. 导出模型族：`model3.json + moc3 + textures + physics3 + motion3`
5. `creature.json` 清单
6. （可选）分层 PNG 降级包

> 不再强求"外包画师出分层 PSD"。若追求高质量，仍可外包，且与本流水线兼容——外包只需交 §4.2 的第 3 项。

### 4.3 台词库

- JSON：`{category, text, weight, cooldownSec, modeTags}`
- 规则：同类 5 分钟不重复、连续两轮不同句、免打扰时段整类跳过。
- `relation` 配置化（默认"爸爸"），不硬编码。

### 4.4 儿童肖像约束（硬约束）

### B.1 状态机（主干串行 + 叠加层）

```ts
class ActionQueue {                     // 主干：单通道，不可抢占
  private current: Motion | null = null;
  private queue: Motion[] = [];
  play(m: Motion, urgent = false) {
    if (urgent) { this.current?.cancel(); this.current = m; m.start(); return; }
    this.current ? this.queue.push(m) : this.startNext();
  }
  update(dt: number) { this.current?.update(dt); if (this.current?.finished) this.startNext(); }
}

class ParamMixer {                      // 叠加层：并行合成，不打断主干
  base: Params;
  layers = new Map<LayerId, { p: Params; w: number; prio: number }>();
  apply(l: LayerId, p: Params, w = 1, prio = 0) { this.layers.set(l, { p, w, prio }); }
  resolve(): Params {
    const out = { ...this.base };
    for (const [, { p, w }] of [...this.layers].sort((a, b) => a[1].prio - b[1].prio))
      for (const k in p) out[k] = mix(out[k] ?? 0, p[k], w);   // 线性插值，禁硬切
    return out;
  }
}

function tryGreet() {
  if (!cfg.features.greeting || inDoNotDisturb() || isFullscreenActive()) return;
  if (!queue.atSafePoint()) { queue.onceSafePoint(tryGreet); return; }
  mixer.apply('look', lookAtCursor(600), 1, 10);
  mixer.apply('wave', waveParams(), 1, 20);
  say(pickLine('greeting'));
}
```

### B.2 穿透判定（Rust）

```rust
async fn hit_test_loop(win: WebviewWindow, st: Arc<Mutex<MaskState>>) {
    let mut last_hit = false;
    loop {
        let s = st.lock().unwrap();
        if s.suspended { drop(s); sleep(Duration::from_millis(100)).await; continue; }
        let (cx, cy) = get_cursor_pos_physical();
        let pos = win.outer_position().unwrap();
        let size = win.outer_size().unwrap();
        let inside = cx >= pos.x as i32 && cy >= pos.y as i32
                  && cx < pos.x as i32 + size.width as i32
                  && cy < pos.y as i32 + size.height as i32;
        let hit = inside && s.mask.sample(
            (cx - pos.x as i32) as f32 / size.width as f32,
            (cy - pos.y as i32) as f32 / size.height as f32, 0.15);
        drop(s);
        if hit != last_hit { win.set_ignore_cursor_events(!hit).ok(); last_hit = hit; }
        sleep(Duration::from_millis(33)).await;
    }
}
```

## 十、v1.3 增补：双生灵方案（冉冉＋小蚂蚁）

> 本节由用户新增需求触发：把布偶蚂蚁改成**活着的陪伴小生灵**——她坐着时抱着它，其他时候它在旁边陪她、在她身边活动。**本节覆盖 v1.2 的 D6（单窗口多生灵）与实际素材范围。**

### 10.1 关系定义

| 角色 | 定位 | 设计约束 |
|---|---|---|
| 冉冉 | 主生灵 | 已定稿母版：玩偶服＋兔耳帽＋抱蚂蚁；4 头身；游戏立绘感平涂 |
| 小蚂蚁 | **伴生灵**（活物，非布偶） | 拟人化 Q 版：保留 **2 手 2 足**，不做 6 足真实蚁形——6 条腿会让绑定与动作曲线成本翻倍；珊瑚粉短绒质感、触角一竖一弯、白色手套与大脚 |

三种状态：`held`（被她抱着）｜`near`（在她身侧驻足、摆触角、眨眼、小幅晃动）｜`roam`（自由爬桌面、追光标、蹦跳 —— **二期**）

### 10.2 架构调整

| 项 | v1.2 做法 | v1.3 改为 | 原因 |
|---|---|---|---|
| 窗口模型 | 单窗口内多个 Renderer | **每个生灵一个 Tauri 窗口**，各自包围盒、独立穿透掩码、独立拖拽；主进程统一调度托盘与配置 | 两个生灵距离会拉开，单窗口要么过大（穿透区域浪费）要么裁切 |
| 抱姿实现 | — | 她的模型暴露 `handAnchor`（由 Live2D 部件坐标换算）；蚂蚁模型按该锚点渲染并跟随，**不把两者合进同一 PSD** | 合并会毁掉她已验证的分层，也让"放下"无法实现 |
| 状态耦合 | 单状态机 | 两套独立状态机 + 事件总线：她坐下→蚂蚁 `held`；她起身/伏案→蚂蚁淡出到凳边转 `near` | 各自节奏不同，绑死会互相拖累 |
| 穿透判定 | 单掩码 32×32 | 每窗口独立掩码；蚂蚁尺寸小，掩码提到 **64×64**；点击判定用包围盒膨胀 12 px 容错 | 小目标的精确掩码会频繁误判 |
| 性能验收 | 单模型 | 双模型同屏；非焦点模型降帧至 10 fps；合计仍按 §5 指标（CPU ≤2% 单核 / 内存 ≤200 MB）验收 | 双模型 + 双 WebView 会抬高基线，必须先测再定 SLA |

### 10.3 一期落地范围（砍掉做不完的部分）

| 状态 | 一期做 | 说明 |
|---|---|---|
| `held` | ✅ 蚂蚁在她怀里，做"探头、抖触角、眨眼"三个循环 | 复用母版，不额外生成 |
| `near` | ✅ 蚂蚁在她身侧驻足：抖触角 / 晃身 / 眨眼 / 偶发仰头看她 | 3–4 个短循环，绑定量可控 |

1. 活物版立绘（站姿正面，珊瑚粉短绒质感，触角一竖一弯）——**已产出**：`art/source/master/01_伴生灵_小蚂蚁活物版.png`

3. 表情差分：好奇（默认）／开心（弯眼）／困倦（半闭眼）

5. 二期：爬行、蹦跳
