# 山海遇灵 · 桌面生灵（过渡预览壳）

这是**能现在就跑起来**的一版，不是最终形态。技术上用 Electron 做透明置顶窗口，目的是先把"能浮在桌面上的实物"给你看；渲染层（素材、状态机、台词、穿透判定）与最终 Tauri 2 版共用，换壳不用重做。

## 怎么启动

```powershell
cd desktop-shell
npm start
```

或直接双击：`desktop-shell\start.bat`

## 场景脚本（`desk-pet.html` 里的 `runScene`）

一个场景是**四件事绑在一起演**，缺一件就会散：姿态序列 → 窗口位移 → 蚂蚁状态 → 台词。

| 场景名 | 序列 | 位移 | 蚂蚁 |
|---|---|---|---|
| `walk` | stand → walkA/walkB × 6~11 半步 → stand → sit | 每半步 26px，方向随机 | `near`，跟着一起走 |
| `rope` | stand → ropeAir↔ropeLand × 7~11 → stand → sit | 原地（窗口不动，靠 CSS 弹跳） | `near` |
| `phone` | stand → 走到边上 → phone 13~20s → stand → 走回 → sit | 先 +1600px（被工作区夹住），再反向 320~700px | `near` |
| `play` | sit → 蚂蚁快走 → 仰头 → 走一圈 | 无 | `near` |

时序常量集中在 `sceneWalk / sceneRope / scenePhone` 里（走路 每姿态 200ms / 每姿态 18px / 起伏 800ms；跳绳每帧 185ms），改行为就改这几个数。

**调试**：环境变量 `PET_SCENE=walk|rope|phone|play` 启动后 3 秒自动演一场；`PET_SCALE=0.8` 启动即按该倍率缩放；`PET_PIN=1` 启动即钉住；`PET_LOCK=1` 启动即锁定（验证穿透用 `tools/check_lock.py`）；`PET_AUTOSTART=1|0` 启动 1 秒后把开机自启写成开/关（无人值守验注册表链路，省得点菜单）。浏览器里用 `#s=walk` 等后缀。`PET_DEBUG_BOUNDS=1` 会把每次 move/resize 写进 `_bounds.log`。换形象验收：`PET_CREATURE=<id>` 指定这次装哪只；`PET_OPEN_SETTINGS=creature|frames|lines` 启动 1.2 秒弹设置窗并停在对应页签；`PET_FRAME_CLONE=1` 启动 1.5 秒把当前形象复制成「用户自定义N」（验素材页/复制链路）；`PET_FRAME_UPLOAD=<帧名>=<图片绝对路径>` 启动 2.5 秒跳过选文件对话框直接走一遍上传校验（日志里看 `[debug] upload {...}`，用来验尺寸/透明底拦截）；`PET_SHOT_PET=<png 路径>` / `PET_SHOT_SETTINGS=<png 路径>` 走 Electron 自己的 `capturePage()` 截图（**透明窗口别用 `tools\shot_window.py` 验，PrintWindow 抓下来是空的**）。

## 开机自启

菜单入口：右键她本人 或 托盘图标 → **设置** → 勾选「开机自启（登录 Windows 后自动出现）」。勾上/取消都是即时生效，不需要重启应用。

实现要点（`main.js` 的 `autostartTarget / autostartCommand / getAutostart / setAutostart / syncAutostartPath`）：

| 事项 | 做法 |
|---|---|
| 写在哪 | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，值名固定 `ShanhaiYuling`；等同于「任务管理器 → 启动应用」里那一条。旧值名 `ShanhaiYulingRanran`（应用名还带"·冉冉"时留下的）启动时会被迁到新名下并删除，不会变成两条自启项 |
| 启动命令 | 开发态：`"…\node_modules\electron\dist\electron.exe" "…\desktop-shell"`；打包态 / 安装版：`"…\山海遇灵.exe"`（`app.isPackaged` 自动判断，设成自启的和当前正在跑的是同一个） |
| 换目录后会不会失效 | 不会：每次启动调 `syncAutostartPath()`，自启开着就按当前 exe 重写一遍（幂等）。从开发态换成安装版、装到另一个盘、拷到第二台机器，跑一次就对上了 |
| 为什么不用 `app.setLoginItemSettings` | 实测它在 Windows 上①回读按 path+args 匹配、刚写完就回读是 `false`，菜单勾选永远对不上；②写出的命令不带引号，项目挪到带空格目录就起不来。这里改为直接用 `reg.exe` 读写，只把它留作注册表被拦时的兜底 |
| 勾选状态从哪来 | 每次开菜单都回读注册表，不在内存里记；用户手动清理过也能如实反映 |
| 关掉做了什么 | 删除该 Run 值（本来就不存在也算成功），不改动其它自启项 |

排查：`_scene.log` 里搜 `setAutostart`，格式 `want=… regOk=… real=… cmd=…`；`regOk=false` 说明注册表写被拦（组策略/杀软），此时会退回 Electron 接口，`real` 是回读结果。

## 生灵包（换一只萌宠不用改代码）

一只生灵 = 一个目录，**全部住在同一个根**：`%APPDATA%\山海遇灵\creatures\`（设置页里就叫「生灵目录」）。冉冉也在里面，和用户自定义的完全同级——首次启动会把程序目录 `assets\` 里的成品复制一份种子过来，之后运行时只读生灵目录，`assets\` 仅作为原始素材留档。

```
生灵目录\
  冉冉\                  内置这只（首次启动从 assets 复制种子）
    creature.json        名字、窗口高度、伴生灵、headTop 覆盖
    frames\              图放这里
      base.png           必需，坐姿
      blink.png stand.png walkA.png …（缺了也能跑，只是对应动作禁用）
    companion\ant_walk.png  伴生灵雪碧图
    lines.json           常用语
  用户自定义1\            设置页「复制为新形象」生成
  用户自定义2\
  说明.txt               给人看的目录说明
```

三条机制：

1. **帧按文件名认领**：文件名按非字母数字切词，词命中规范帧名就认领（`小兔_base_2x.png` → `base`，`ranran_ntBlink_2x.png` → `ntBlink` 而不会误认成 `blink`）。同帧有多份时优先 `frames/` 子目录、其次名字带 `2x` 的；`creature.json` 里写 `frames.<name>.file` 可显式指定。
2. **头顶锚点自动量**：主进程把图缩到 384 宽扫 alpha，取最上一行不透明像素换成 0~1 比例，气泡按比例贴头；不用再手填 `HEAD_TOP`。
3. **缺图就降级，不报错**：渲染层按实际加载到的帧反算能力（走动/跳绳/玩手机/陪伴生灵）回报主进程，菜单项显示"（这套图没有对应帧）"并置灰；自主日程只从可用帧里抽；没有伴生灵就不出现蚂蚁，也不说关于蚂蚁的话。

4. **帧轨道由清单决定（v2，可选）**：`creature.json` 可写 `tracks` / `sequences` / `phases`（语法见 `docs/生灵包规范.md` 第 9 节），把"眨眼 150ms、走一步 200ms、跳绳 185ms、转头→回坐姿→笑"这些节拍从代码收进清单；不写 `tracks` 就按现有帧合成默认轨道，行为与旧版一致。轨道只改"何时换哪一帧"，淡入/硬切/穿透上报仍由渲染层按帧名决定。校验是 fail-closed：坏轨道丢弃记错误，缺帧/非法时长/fallback 悬空或成环记警告；设置页「帧轨道」一行显示轨道数与诊断数（悬停看明细），命令行用 `node desktop-shell\tools\validate-creature.js <生灵目录>` 核对。

加新形象的操作路径：设置页 → 素材 →「复制为新形象」（自动编号 `用户自定义N`，整套帧连同伴生灵、图标、台词一起复制）；或设置页 → 形象 →「打开生灵目录」→ 新建文件夹 → 丢图进 `frames/` →「重新扫描」→ 下拉框里就多一项。**不用装 Python**：设置页会直接标出缺哪几帧、哪几张尺寸不一致，说明就写在「生灵目录怎么摆」那段里；`tools\check_creature.py` 只给做素材的人批量核对（可选）。生灵目录里常驻一份 `说明.txt`，别人打开文件夹就知道怎么放图。

### 素材页（不碰文件也能换帧）

设置页 → 素材，25 个动作帧一行一张：左边是透明底预览（走 `pet://thumb/…`，主进程现缩到 128px，不为了 76px 的格子去解码整张 900×1360），中间是帧名 + 这个动作干什么 + 当前文件，右边「上传 / 替换」「清除」。

- **上传落到哪**：`<生灵目录>\frames\<帧名>.png|webp`，同时往 `creature.json` 的 `frames.<帧名>.file` 写显式绑定（不再靠文件名猜）。写完走 `applyCreature` 热切换，`caps`/缺帧清单当场重算，菜单里"（这套图没有对应帧）"跟着变，不用重启。
- **挡掉什么**：非 PNG/WebP（JPG 没有透明通道）、读不出的文件、尺寸与 base 不一致（换帧会跳大小）、四角不透明的（白底图会连背景贴到桌面）。挡下来时不写任何文件。
- **复制为新形象**：把当前这只整套复制成 `生灵目录\用户自定义N`（N 取第一个空号）并立即切过去，之后两只各改各的。只搬 25 张认过的帧 + 伴生灵 + 图标 + `lines.json`，`_raw` / `_matted` 那些中间产物不带过去。
- **清除**只删 `frames/<帧名>.png|webp` 这一份自己落盘的文件并解除绑定；用户手放的素材（比如根目录的 `xxx_wave.png`）一律不删，只提示"来自目录里的某文件，要彻底去掉请自己删"。

完整规范（25 个帧名的含义、creature.json 字段表、降级规则表、画图硬要求）在 `..\docs\生灵包规范.md`；设置页长这样：`..\docs\设置页_形象.png`、`..\docs\设置页_常用语.png`。

常用语存在 `%APPDATA%\山海遇灵\settings.json`：`{ creatureId, mode, lines: { <生灵ID>: [ … ] } }`，按生灵分开；没改过的生灵用自己目录里的 `lines.json`，点「恢复默认」就删掉覆盖。

## 已知限制

1. **透明窗口在部分 Windows 机器上会因显卡驱动显示为黑底**。若出现黑块，先在 `main.js` 里试 `win.setBackgroundColor('#00000000')` 保留、并把系统"透明效果"打开；仍不行则说明该机 GPU 合成受限，需换 Tauri + 原生分层窗口。
2. **开机自启的开发态绑定的是当前 `electron.exe` 的绝对路径**：重装依赖或挪走项目后，注册表里那条会指向不存在的路径（此时自启静默失败）。只要用新路径的副本启动一次，`syncAutostartPath()` 就会把它改回正确路径；彻底不想要就去菜单里取消勾选。
3. 若在「任务管理器 → 启动应用」里手动把它**禁用**，注册表值仍在，本菜单仍显示勾选（我们只读 Run 键，不读 `StartupApproved` 的禁用位），此时不会真的自启——要彻底关掉请在菜单里取消勾选。
4. 拖拽时如果鼠标移出精灵包围盒，可能丢掉 `pointerup`（已用 `setPointerCapture` 缓解，极端情况会停在拖拽态，点击一次即可恢复）。

## 关于"网游那种丝滑"是怎么做到的

网游（尤其 MMO）里角色动作不僵硬，靠的是四层机制，而不是"帧画得多"：

1. **骨骼/参数驱动**：角色不是一堆图，是骨骼（Spine）或参数网格（Live2D）。动作是骨头角度随时间变化，任意中间态都能画出来，所以永远连续。
2. **动作混合（blend）**：走路→停下→挥手，不是切动画，而是在 0.2~0.4 秒里把两个姿态按权重插值（crossfade blend），所以过渡没有"啪"的一下。
3. **状态机 + 动作层**：底层管身体（站/走/坐），上层叠加表情与手势（additive），互不打断。
4. **次级动作（secondary motion）**：头发、裙摆、耳朵、触角、尾巴用弹簧/惯性跟随主骨骼滞后摆动。这是"活着"的关键——主运动停了，末梢还在晃。

对应到我们：
- 第 1、2 条必须换渲染方式（`.moc3` 参数驱动 / Spine 骨骼），**整帧切换永远做不到**；
- 第 3 条已经在做（`held`/`near` 状态机 + 表情层）；
- 第 4 条现在只在小蚂蚁身上有（倾斜 + 上下浮 + 挤压三层叠加），她的头发/兔耳还不会独立晃——这需要把立绘**分层切成头/耳/发/身/手**，才能让耳朵跟着头滞后摆。

所以下一步的真正分水岭是**分层**：把现有立绘拆成部件（头、兔耳、前发、后发、身体、手臂、裙摆、腿），有了部件就能做骨骼绑定 + 次级动作，再交给 PSD2Live 自动绑出 `.model3.json + .moc3`。
